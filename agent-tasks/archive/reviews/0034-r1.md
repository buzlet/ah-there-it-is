## Self-review

- **Wait bounds:** Git inspection has a 15-second subprocess limit, Codex version probing is bounded, branch lock acquisition is non-blocking, Codex tails are bounded by the existing runner, canonical recipes have finite timeouts, and CI uses the 30-minute bounded waiter. Tests use bounded waits.
- **Duplicate processes:** a `flock` is keyed by Git common directory and task branch and inherited by the detached supervisor. A second start returns the existing owner while the lock/process group is active. Continuation requires the exact previous run ID, a free lock, a terminal or stale process state, unchanged assignment/control identity, and a new run ID. Stale/invalid identity is never treated as running success.
- **State placement:** prompts, metadata sidecars, lock records, Codex traces, verifier state, CI observations, and lifecycle checkpoints are external to the Git worktree. Prompt and state helpers reject worktree paths.
- **Secrets:** prompts are passed by file descriptor/stdin and only prompt hashes enter metadata. Continuation accepts fixed validated state fields, not arbitrary notes. The helper does not serialize environment variables or authentication material; the fake-process test checks a sentinel is absent from durable state.
- **Prompt and command safety:** prompt content is sourced byte-for-byte from `git show` at the supplied control SHA and is never shell-interpolated. Git, Codex, and `gh` calls use argument arrays; no `shell=True` or shell command construction is used.
- **Application coupling:** all additions are under agent tooling, tests, and documentation. The helper is not installed as an application entry point and adds no dependency.
- **Merge authority:** recovery recognizes a merge only when the task branch tip, including a commit beyond the seed, is an ancestor of the configured main ref. A seed-only merge is not reported as task completion. Unexpected main advancement is a blocker.
