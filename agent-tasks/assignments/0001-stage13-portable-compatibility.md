# Assignment 0001: Stage 13 portable compatibility contract

Protocol: `agent-tasks/common/v1.md`

Repository: `buzlet/ah-there-it-is`
Branch: `feat/stage13-portable-compatibility`

## Objective

Freeze `inventory-portable-v1` as an executable compatibility contract so future database/schema work cannot silently break archives created under v1.

## Required implementation

1. Add a committed, hand-authored `inventory-portable-v1` JSON fixture under the test fixture tree.
   - It must not be generated by the current exporter.
   - Give it fixed timestamps and stable IDs.
   - Include nested categories and locations.
   - Include multiple items covering aliases, tags, structured attributes, current location/category references, quantity/state, and domain history.
   - Use a real older Alembic revision from this repository in `source.alembic_revision`, not the current head.
   - Keep operational/provider/evaluation/chat-request data absent exactly as the portable format requires.

2. Add compatibility tests using that fixture.
   The executable path must cover:
   `fixture -> load/validate -> import into a fresh current-schema DB -> SearchService queries -> re-export`.

3. Assert the imported/re-exported domain is semantically equivalent to the fixture:
   - preserve portable stable category/location/item/event IDs and portable timestamps;
   - preserve hierarchy, item state/quantity, attributes, aliases, tags, current locations/categories, event payload/text and location references;
   - compare aliases/tags as order-insensitive collections where ordering is not part of the format;
   - ignore only intentionally volatile exporter metadata such as the new `exported_at` value;
   - do not require the exported `source.alembic_revision` to remain the old source revision, because the re-export comes from the newly migrated current database.

4. Prove current search-derived state is reconstructed rather than serialized:
   - include fixture data that is findable through item name plus at least one alias/tag/attribute or description query;
   - query it through the existing `SearchService` after import.

5. Make version handling explicit.
   - Keep `inventory-portable-v1` immutable.
   - Introduce a small explicit format-version dispatch boundary for parsing/loading instead of allowing future format evolution to accumulate as permissive conditionals inside the v1 parser.
   - Current behavior for unsupported format identifiers must remain a clear validation error.
   - Do not add a v2 format in this task.

6. Older `source.alembic_revision` is metadata only.
   - The v1 fixture with the older real revision must import through the current importer.
   - Do not execute old migration code based on the source revision.
   - Do not relax current domain validation because the fixture is old.

7. Keep recovery products separate.
   - Do not add conversations, chat-request/recovery audit, agent/evaluation/experiment/provider traces to portable import or compatibility fixtures.
   - Do not change full SQLite backup/restore semantics.

8. Update user-facing portability documentation only where needed to state the v1 immutability/version-dispatch compatibility rule.
   - Do not mark Stage 13 complete.
   - Do not invent Stage 14. Stage-status finalization is owned by the orchestrator after PR verification.

## Constraints

- No provider/model changes.
- No voice/Telegram/images/QR/MCP/PWA/cloud/embeddings/multi-user work.
- No dependency or GitHub Actions version changes.
- No unrelated refactoring.
- Follow `agent-tasks/common/v1.md`: no tests/checks/CI inspection unless a later orchestrator instruction explicitly requests one.
